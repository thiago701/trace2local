# Dossiê de evidências — TraceVanta

> Levantamento feito em **2026-09-18** por três frentes paralelas da Squad AI, com fonte primária para cada afirmação.
> Este documento existe para que a [SPEC](SPEC.md) e os [ADRs](adr/) possam ser auditados: qualquer decisão pode ser rastreada até o fato que a sustenta — ou até a admissão de que o fato não foi encontrado.

**Regra de leitura:** *Confirmado* = verificado na fonte citada nesta data. *Não confirmado* = procurado e não encontrado; não é o mesmo que falso. *Inferência* = conclusão da squad a partir dos fatos, não afirmação da fonte.

---

## 1. Achados que mudaram o desenho

Cinco fatos derrubaram ou reescreveram partes da especificação original.

### 1.1 `onEnd` do SpanProcessor é somente leitura → o delta de dados não cabe no span

`SpanProcessor.onStart` recebe `ReadWriteSpan` (mutável); `onEnd` recebe `ReadableSpan` (imutável). O javadoc de ambos diz que são chamados "synchronously on the execution thread, should not throw or block". Como o resultado de uma operação só é conhecido no fim, **não há como enriquecer o span com o `after`**. → Origem do [ADR-003](adr/ADR-003-canal-lateral-de-mutacao-de-dados.md) (canal lateral). *Confirmado — código-fonte do SDK.*

### 1.2 Lambda não hospeda UI → dois modos de execução

Ciclo Init→Invoke→Shutdown com congelamento entre invocações; processos de background pausam junto. Não existe processo de longa duração no ambiente da função. → Origem do [ADR-002](adr/ADR-002-dois-modos-de-execucao.md) (modo Companion/Station) e da regra de flush síncrono. *Confirmado — documentação AWS.*

### 1.3 "Spring Boot 3.4+" está defasado

Spring Boot **4.0.0** GA em 20/11/2025; estável em 18/09/2026 é **4.1.1**; baseline JDK 17 com suporte de primeira classe a Java 25. Spring Framework **7.0** GA em 13/11/2025. → §7.2 da SPEC corrigida. *Confirmado — blog oficial Spring.*

### 1.4 Mensageria e AWS ainda são *development* no semconv

Atributos de banco estão **estáveis**; a página inteira de mensageria e todos os atributos AWS estão em **Development** — podem mudar em release menor. → Origem do [ADR-008](adr/ADR-008-camada-semantica-anticorrupcao.md) (anti-corrupção). *Confirmado — specs do OTel.*

### 1.5 Existe um vizinho arquitetural: Glowroot

Agente Java com UI embutida em `localhost:4000`, Apache-2.0, ativo (0.14.7, maio/2026). "UI local embutida para Java" **não é novidade**; o diferencial precisa ser dito como *catálogo clicável + DAG cross-serviço + delta before/after*. → §2 da SPEC reescrita. *Confirmado — repositório do projeto.*

### 4.1 Arte prévia

| Projeto | Licença | O que é | Sobreposição |
| :--- | :--- | :--- | :--- |
| **Glowroot** | Apache-2.0 | `-javaagent` + UI em `localhost:4000`, call tree, H2 local | **Alta em arquitetura**, baixa em proposta: profiler passivo, sem catálogo, sem disparo, sem delta, incompatível com AOT |
| Jaeger all-in-one | Apache-2.0 | Collector + UI em um binário | Média — processo separado, sem catálogo/disparo |
| Zipkin | Apache-2.0 | `java -jar zipkin.jar`, UI em :9411 | Média — precedente de "single jar local" |
| otel-desktop-viewer / otel-gui | Apache-2.0 / MIT | Visualizadores OTLP locais (2025–2026) | Baixa — recebem, não instrumentam nem disparam |
| otel-tui | Apache-2.0 | Mesma categoria, no terminal | Baixa |
| Digma | — | Plugin de IDE correlacionando código e runtime OTel | Baixa — superfície é o editor |
| Actuator `httpexchanges` | Apache-2.0 | Últimas 100 trocas em memória | Baixa — o Spring documenta que **não** é tracing |
| Helios/Aspecto | — | **Adquirida pela Snyk em jan/2024**, absorvida na linha ASPM | Não existe mais como produto independente |

**Veredito:** não foi encontrada biblioteca que combine UI embutida no JAR + catálogo clicável com disparo + DAG cross-serviço com delta before/after. *Confirmado dentro do alcance da busca* — ausência de evidência não é evidência de ausência, e uma nova varredura antes do anúncio é prudente.

## 5. O que ficou sem resposta

Registrado aqui para não virar suposição silenciosa mais adiante:

1. **Overhead do SDK OTel sem agente** — nenhum benchmark público isolando esse caminho. Consequência: todos os NFRs de performance (§7.1) são **alvos**, marcados `[A MEDIR]`, e a linha de base precisa ser medida no próprio projeto.
2. **Cold start de GraalVM native em Lambda** — sem número primário da AWS.
3. **Custo de OTel no INIT da Lambda** — apenas relatos qualitativos.
4. **Baseline mínimo de JDK do Quarkus** — não confirmado; irrelevante até a v0.3.
5. **Transporte preferido em dev-tooling** — sem censo; a escolha por SSE é argumentada, não referendada.
6. **Disponibilidade do nome "TraceVanta"** (GitHub, npm, marca) — não pesquisada; tarefa do M0.

## 6. Método

Três agentes em paralelo, cada um com objetivo, critério de aceite e formato de retorno definidos, instruídos a **separar fato confirmado de inferência** e a relatar explicitamente o que não encontraram — incluindo evidência contrária ao enunciado que receberam. Foi assim que a defasagem do "Spring Boot 3.4+" e a existência do Glowroot entraram no dossiê: nenhuma das duas estava na pergunta.

Fontes primárias preferidas: repositórios e código-fonte oficiais, `openjdk.org/jeps`, `docs.aws.amazon.com`, `opentelemetry.io`, `spring.io`, `central.sonatype.org`. As URLs completas estão em §15 da [SPEC](SPEC.md).
